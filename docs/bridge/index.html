⚔ Combat Tracker Bridge Protocol

The WebSocket protocol between the D&D Combat Tracker desktop app and its Stream Deck plugin — documented so anything else can integrate the same way: stream overlays, macro pads, home-automation buttons, other tools.

Connection

The desktop app hosts a plain WebSocket server on ws://127.0.0.1:57321 (port configurable in the app under Settings → Stream Deck bridge). No authentication, no handshake beyond the WebSocket upgrade — the server only listens on the loopback interface. Any number of clients may connect; the Stream Deck plugin is simply one of them, and the connection count shows in the app's sidebar.

  • On connect, the app immediately pushes a full state message.
  • Every state change pushes a fresh, complete state message to all clients — there are no deltas.
  • Clients send single JSON command objects; the app never replies to commands directly (the resulting state broadcast is the acknowledgement).
  • If the app is closed, reconnect with your own retry loop — the plugin retries every 3 s forever.

State message (app → client)

Sent on connect and on every change. Outside an active combat, combatants is empty and round is 0. 

{
  "type": "state",
  "language": "en",              // "en" | "de" - the app's UI language
  "currentIndex": 2,             // index into combatants of the active turn
  "round": 3,
  "combatants": [
    {
      "id": "6f0c…",             // stable per combat; use for commands
      "sourceId": "a1b2…",       // monster template id (PCs: library PC id)
      "displayName": "Goblinkrieger 2",  // localized to `language`
      "currentHp": 4,
      "maxHp": 10,
      "ac": 15,
      "isCurrentTurn": true,
      "isDowned": false,          // PCs at 0 HP stay listed, downed
      "conditions": ["Poisoned"], // canonical English values (see below)
      "attacks": [                // rollable actions only
        {
          "id": "srd-2024_goblin.scimitar",
          "name": "Krummsäbel",   // localized to `language`
          "toHit": 4,             // null for save-based actions
          "save": null,           // e.g. "GES 13" (localized ability + DC)
          "damage": [
            { "dice": "1d6+2", "average": 5, "type": "slashing", "condition": null }
          ]
        }
      ]
    }
  ]
}
Monsters removed at 0 HP disappear from combatants entirely. Player characters stay, with isDowned: true. Names, attack names and save abilities arrive already localized; conditions values are always the canonical English strings.

Commands (client → app)

One JSON object per WebSocket message.

CommandPayloadEffect
nextTurn {"type":"nextTurn"} Advance the turn; wraps to the next round.
prevTurn {"type":"prevTurn"} Rewind the turn; refused at round 1, first actor.
endCombat {"type":"endCombat"} End the combat immediately (no confirmation on this side).
applyDamage {"type":"applyDamage","actorId":"6f0c…","amount":7} Damage floors at 0 HP; monsters die and leave the order, PCs go down.
applyHeal {"type":"applyHeal","actorId":"6f0c…","amount":5} Healing caps at max HP; revives downed PCs.
toggleCondition {"type":"toggleCondition","actorId":"6f0c…","condition":"Poisoned"} Adds or removes the condition (canonical English value).
attackEvent {"type":"attackEvent","sourceId":"a1b2…","attackId":"srd-2024_goblin.scimitar","phase":"attackHit"} Attack-flow progress report. No state change — it only triggers Kenku FM sounds the DM has configured for that attack or for the global crit/hit/miss events. sourceId is recommended but optional: the app can resolve the attack from attackId alone (action ids are unique).

attackEvent phases

  • attackRoll — the d20 left the cup (fires regardless of outcome)
  • attackCrit / attackHit / attackMiss — the verdict (send exactly one; a crit implies a hit)
  • damageRoll — damage dice rolled
  • damageApplied — the damage was committed (send alongside applyDamage)

Condition values

Blinded, Charmed, Deafened, Exhaustion, Frightened, Grappled, Incapacitated, Invisible, Paralyzed, Petrified, Poisoned, Prone, Restrained, Stunned, Unconscious

Example session

> (connect ws://127.0.0.1:57321)
< {"type":"state","language":"en","currentIndex":0,"round":1,"combatants":[…]}

> {"type":"applyDamage","actorId":"6f0c…","amount":7}
< {"type":"state", …updated combatants…}

> {"type":"nextTurn"}
< {"type":"state","currentIndex":1, …}

> {"type":"endCombat"}
< {"type":"state","combatants":[],"round":0, …}

Behaviour notes

  • Unknown command types are ignored silently — safe to feature-detect by trying.
  • Malformed JSON closes nothing; the message is dropped.
  • Pressing hardware keys pulls the app's DM window to its Combat screen; attackEvent deliberately does not.
  • The protocol is unversioned; fields are only ever added, never repurposed. Treat unknown fields as forwards-compatible.
